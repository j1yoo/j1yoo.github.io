# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository overview

Personal academic website of Jaewon Yoo (j1yoo.github.io), built on the [al-folio](https://github.com/alshedivat/al-folio) Jekyll theme and deployed to GitHub Pages. The theme's generic docs live in README.md, INSTALL.md, CUSTOMIZE.md, and FAQ.md; the content that is actually personalized lives in `_bibliography/`, `_data/`, `_pages/`, `_news/`, `_posts/`, `_teaching/`, and `assets/`.

## Commands

```bash
bundle install                    # install Ruby deps (Jekyll + plugins)
bundle exec jekyll serve          # local dev server at localhost:4000
bundle exec jekyll build          # build site into _site/ (JEKYLL_ENV=production for prod build)
docker compose up                 # alternative: containerized dev server

npx prettier . --check           # check formatting (uses @shopify/prettier-plugin-liquid, printWidth 150)
npx prettier . --write           # fix formatting

npm run pdf                       # regenerate assets/pdf/cv_jaewon.pdf via Puppeteer
                                  # (requires a prior `bundle exec jekyll build`)

python3 check_links.py            # check internal links in the built _site/
```

There is no test suite. Pre-commit hooks (`.pre-commit-config.yaml`) enforce trailing whitespace, EOF newlines, YAML validity, and large-file limits.

## CI / deployment

- **deploy.yml**: on push to `main`, builds the site (Ruby 3.3.5, Python nbconvert, ImageMagick), purges unused CSS, and deploys `_site/` to GitHub Pages.
- **generate-pdf.yml**: on push to `main`, rebuilds the site, runs `npm run pdf`, and commits `assets/pdf/cv_jaewon.pdf` back with message `Update CV PDF [skip ci]`. Never hand-edit that PDF — it is generated. Expect these bot commits interleaved in history.
- **prettier.yml**: auto-formats with Prettier and pushes fixes; write Liquid/HTML/Markdown to survive `prettier --write` rather than fighting it.
- Other workflows: lychee broken-link checks, axe accessibility (manual), Lighthouse badges, CodeQL, Docker images.

## Architecture

### Publications / research page

The research page (`_pages/publications.md`, served at `/research/`) is generated by jekyll-scholar from `_bibliography/papers.bib`. Two custom mechanics matter:

- Every bib entry carries a custom `kind={...}` field, one of: `manuscripts in revision`, `manuscripts under review`, `working papers`, `work-in-progress`, `publications`. The page loops over these categories and, within each, over years — including the special year values `current` and `forthcoming` (unpublished entries use `year={current}`).
- Rendering templates: `_layouts/bib.liquid` (website) and `_layouts/bib_clean.liquid` (CV PDF). Supported extra bib fields include `abbr`, `award`, `arxiv`, `bibtex_show`, `html`, `pdf`, `slides`, `video`, `abstract`, etc.

### Bibliography conventions (`_bibliography/papers.bib`)

- 미게재 항목(bib entry)의 키에는 연도를 넣지 않는다. 게재 확정 후에만 연도 키 사용.
  - Non-published entries (manuscripts in revision / under review / working papers / work-in-progress, i.e. any entry whose `kind` is not `publications`) must use year-less keys, e.g. `yoo_helpinghands`.
  - Keys with a year (e.g. `yoo2018compromise`) are reserved for entries with `kind={publications}` once publication is confirmed.
- Blind-review placeholders are legitimate entries (e.g. key `blind_review`, title `[Title and authors withheld; under blind review]`); details are sometimes intentionally withheld or hidden in source — check git history before "fixing" them.

### CV pipeline

The CV is generated from site content, not maintained by hand:

1. `_pages/cv_print.md` (layout `cv_clean.liquid`, at `/cv_print/`) renders the bibliography by `kind` plus data from `_data/`.
2. `_scripts/generate_pdf.js` (Puppeteer) prints the built `_site/cv_print/index.html` to `assets/pdf/cv_jaewon.pdf`.
3. `_pages/cv.md` (at `/cv/`) simply embeds that PDF in an iframe.

So to change the CV, edit the underlying content (bib entries, `_data/*.yml`, `cv_print.md`) — not the PDF.

### Data files (`_data/`)

`talks.yml` drives the talks page (title/venue/date/slides/website/note per entry); `cv.yml`, `coauthors.yml`, `venues.yml`, `supervision.yml`, `socials.yml`, `repositories.yml` feed their respective pages. The CV page content can also come from `assets/json/resume.json` (jsonresume standard) with `_data/cv.yml` as fallback.

### Collections and content

Custom collections beyond blog posts: `_teaching`, `_books`, `_news` (shown on home page), `_projects`, `_gallery_events`. Custom Ruby plugins in `_plugins/` handle Google Scholar citations, external post fetching, cache busting, etc.

## Branch planning convention

This repo uses a branch-plan workflow (see `.claude/skills/branch-plan/SKILL.md`, invoked as `/branch-plan`): each work branch gets a `CLAUDE.<branch-name>.md` plan file referenced from `CLAUDE.local.md`, kept up to date as the single source of truth for that branch's state. Update the active plan file before and after each task.
